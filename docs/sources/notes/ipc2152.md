# IPC-2152: nature of the standard, third-party fits, twc (S-002, S-011a..e, S-050)

Retrieved 2026-10-06. IPC-2152 was not read (paywalled). Everything below is secondhand or comes from third-party tools.

## Bottom line for `ipc2152-policy` and Mode A
- **"IPC-2152 itself provides charts, not a closed-form equation"**: every source found supports this, but none of us has read the standard, so the claim stays PAYWALLED-USER-MUST-VERIFY. Sources:
  - Z. Peterson, Altium Resources (2019, updated 2022): "there is no explicit formula"; results "summarized in a set of charts".
  - Brooks & Adam, PCD&F 2015-05-29: they digitized IPC-2152 curves and fit their own equations.
  - Sierra Circuits: "analyzed these graphs and incorporated curve-fitting equations".
  - SMPS.us: results "obtained by interpolation of the IPC plots".
  - M. Jouppi (IPC-2152 committee chair), PCD&F 2009: a main document plus an appendix; describes charts only.
- **"No closed form for IPC-2152 data exists anywhere"**: WRONG. Several published closed-form *fits to IPC-2152 chart data* exist. The best documented is Brooks & Adam (2015): external traces ΔT = 215.3·I²·W^−1.15·Th^−1.0 (W, Th in mil). KiCad's development branch now uses this fit in its track-width calculator (doxygen: "fit to closed-form equations by Douglas Brooks and Johannes Adam"). KiCad 9.0 stable docs still say IPC-2221.
- Mode A can keep the label "IPC-2152-informed estimate", but the reason should be stated precisely: the standard publishes charts; any equation is a third-party fit with its own error versus the charts.
- **Policy question for the orchestrator/human.** CLAUDE.md says never digitize IPC charts. Brooks & Adam, NinjaCalc and SMPS/Olson all *did* digitize them. Using an already-published third-party fit (with citation) is not the same act as digitizing ourselves. Whether it is acceptable is a policy and legal decision for the human, not for the researcher.

## The three twc "IPC-2152 methods" (S-050)
Read from https://github.com/ymic9963/twc (README, docs/METHODS.md, twc.c, twc.h, branch main, 2026-10-06). The code was read, not copied (GPL-3.0). twc docs/METHODS.md says each method is "derived from" a web calculator:

| twc method | Derived from (per twc) | What it computes |
|---|---|---|
| A (default) | NinjaCalc (mbedded.ninja), https://ninjacalc.mbedded.ninja/calculators/electronics/pcb-design/track-current-ipc2152 | An uncorrected area from a power law in I and ΔT with a ΔT-dependent exponent (constants as transcribed: 0.089710902134, 0.39379253898, 0.50382053698, 0.038495772461). Then multiplies by four fitted correction factors: copper weight (6×4 polynomial in current and copper weight), board thickness (power law 24.929779905·h^−0.75501997929), plane distance (linear 0.0031298662911·d + 0.40450883823), and board thermal conductivity (linear, −1.4210148167 / 1.1958174134). No input range checks. |
| B | SMPS.us, https://www.smps.us/pcb-calculator.html | Ac = (110.515·ΔT^−0.871 + 0.803)·I^(0.868·ΔT^−0.102 + 1.129), plus correction factors: copper weight (log-current fits for 1 oz and others), thickness (25.959·h^−0.7666), plane area (0.89 / 0.94 / 1.0 steps), plane distance (0.0031·d + 0.4054 when ≤ 125 mil). twc notes the SMPS website shows a different equation than the SMPS source code. |
| C | Sierra Circuits web app, https://twcalculator.app.protoexpress.com/ | Separate internal/external power laws in ΔT^0.5, copper thickness and width (exponent 1/0.575), with K1 = min(0.09, 0.0458·e^(0.36235/t)) and K2 = 0.068152. No correction factors. twc notes Sierra uses "a wrong resistivity value" for resistance. |

**Conclusion:** all three are empirical curve fits taken from third-party web calculators. None is an equation published in IPC-2152, and none is a table lookup of IPC data. twc cites the calculator websites, not the standard. Constants above were transcribed through a summarizing fetcher. They are for orientation only; re-read twc at a pinned commit before using any in `tests/crosscheck/`.

## Cited sources, checked independently
- **NinjaCalc (Method A):** the page redirects to https://blog.mbedded.ninja/pcb-design/how-to-calculate-maximum-track-current/ and the article body could not be fetched. A search-engine snippet says the data were extracted from IPC-2152 graphs with WebPlotDigitizer and trend lines fitted. Unconfirmed. NinjaCalc's GitHub repo (gbmhunter/NinjaCalc) is deprecated, and the fetcher showed no license for it.
- **SMPS.us (Method B):** the current website shows Ac = (117.555·ΔT^−0.913 + 1.15)·I^(0.84·ΔT^−0.108 + 1.159), fitted for ΔT 2 to 100 °C to IPC-2152 Fig. 5-2 (polyimide, 0.070 in, 3 oz, still air). It credits Jack Olson (Caterpillar) for the coefficients. **CONFLICT** with the coefficients twc took from SMPS source code (110.515 ...). Altium's Peterson article reproduces "their interpolation formula", but only as an image, so we could not tell which set.
- **Sierra Circuits (Method C):** the equations are not published. The page says only that they are curve fits to IPC-2152 graphs.

## Brooks & Adam fits (S-011a/b)
- External traces: ΔT = 215.3·I²·W^−1.15·Th^−1.0, "temperature change from 20°C", I in A, W and Th in mil. Source: PCD&F 2015 Eq. 5, fitted to digitized IPC-2152 Figure 5-1 curves. UNVERIFIED (single primary source; KiCad is tier 4 and derived from it).
- Internal traces: only KiCad's doxygen gives coefficients (per copper weight). The PCD&F text says the internal equations vary with trace width. UNVERIFIED. The paper PDF (mathscinotes mirror) could not be text-extracted.
