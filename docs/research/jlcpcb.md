## 1) What it is / scope

- It is a **width synthesiser tied to the fab's own stackups**, not a general impedance analyser. [CALC] says it "computes track width values and recommended stack-ups" from layer count, thickness, copper weight, target impedance, trace spacing and trace-to-copper gap.
- The direction is target Z0 → width (synthesis). No analysis mode (width → Z0) was found on the page.
- The output is coupled to JLCPCB's catalogue of stackup templates (e.g. `JLC04161H-7628`). The tool ranks those templates. It does not take an arbitrary user-defined dielectric. No user-enterable Er or dielectric height field was seen in [CALC] or [GUIDE].
- Impedance control as a service is listed for **4–32 layer** boards in [CAP] ("Impedance Tolerance: ±10%"). Whether the calculator accepts 2-layer boards was **not found**.
- Board types offered in the UI: "Rigid", "HDI" [CALC].
- JLCPCB has **no trace-width or current calculator tool** on its site that I could find. The only trace-width item is the blog post [BLOG-TW], which gives Python code for users to run themselves (see §7, which describes a serious flaw in it).

## 2) Inputs & structure types

From [GUIDE] (11 inputs) and [CALC] labels:

| Finished thickness | "including soldermask" [GUIDE] |
| Internal copper | 0.5 oz or 1 oz only; 2 oz means contacting support [GUIDE]. The [CALC] dropdown also showed 2oz (conflict, see §7) |
| External copper | Limited to 1 oz "due to tolerance and current-carrying requirements" (paraphrase of [GUIDE]). The [CALC] dropdown showed 1oz, 2oz |
| Unit | mm, mil, µm, inch [GUIDE][CALC] |
| Impedance (Ω) | Accepted range "20 to 90 Ω for single-ended", "50 to 150 Ω for differential" [GUIDE] |
| Type | "Coplanar Single Ended", "Coplanar Differential Pair", "Single Ended (Non coplanar)", "Differential Pair (Non coplanar)" [GUIDE] |
| Layer / Signal Layer | Signal layer |
| Reference layer above / below ("Top Ref", "Bottom Ref") | Reference "does not need to be one layer below the signal", but "there must be a ground plane" on that layer [GUIDE] |

| Impedance trace to copper | Coplanar gap: "The gap between the signal conductor and the surrounding ground" [GUIDE] |

- The UI supports several impedance lines per job: buttons "New Impedance", "Duplicate Impedance", "Calculate" [CALC].
- Structure types **not** offered (nothing found): broadside-coupled pairs, asymmetric stripline with a user-set height, embedded microstrip as a separate choice, and any user Er, loss tangent, frequency or roughness input.
- **Solder mask:** the user cannot set it. It is applied implicitly with fixed parameters (§4).

## 3) Outputs & result presentation

- Outputs are a trace width per impedance line plus a list of compatible stack-up templates. [CALC] says: "The first stack-up calculated below is highly recommended as it has lowest cost and quickest turn-around." [GUIDE] says "usually has the lowest cost and quickest turn-around."
- [Q794] says the recommended stackup has a "red thumbs-up icon". A user example there shows a width of "42.39 mil" for 50 Ω coplanar SE, L1 referenced to L3, 10 mil gap, on JLC04161H-7628. The output is printed to 0.01 mil, which suggests much more precision than the process has (track tolerance is ±20%, see §4).
- No result breakdown was found: no Er_eff, no Z0 for the chosen width, no intermediate steps, no formula, no tolerance band.
- Warnings or validity messages in the UI: **not found** (the JS-rendered content was not visible). Mobile layout: **not observable** with the tools available ("not found").
- No client-side data file or JSON was visible through normal page fetches. [GS] says JLC has a "web API for impedance templates", but the endpoint path is not given in its README. I did not look for it further, per instructions.

## 5) Disclaimers / accuracy statements

- [GUIDE]: "The values provided above are for reference only." It also says some values were "calculated from test results by JLCPCB and may be adjusted in the future".
- [GUIDE]: "The correct material should be selected when ordering", meaning results are only valid for the named template and material.
- [CAP]: impedance tolerance "±10%" is a **manufacturing** tolerance. No accuracy is stated for the **calculator** itself.
- No solver or model name, validity range, frequency, roughness or loss statement was found.
- Data quality: [Q590] lists template errors (exclamation marks instead of numbers, missing copper or prepreg thickness on several 6 L and 16 L templates). [GS] says "JLCPCB's data often contains typos and errors" and notes that JLC labels S1000-2M as "TG170" while the datasheet gives 180 °C.

## 6) UX patterns worth adopting

1. **Template-bound workflow**: choose a fab stackup preset and get dimensions that match it. This fits our rule-9 fab profiles. We should version and date-stamp the presets.
2. **Multiple impedance lines per job** ("New / Duplicate Impedance") and a summary table for all of them.
3. **Reference-layer pickers** that allow non-adjacent references, with a rule that the reference must be a plane.
4. **Unit selector with four units** (mm / mil / µm / inch).
5. **Accepted-range guard on target Z0** (20–90 Ω SE, 50–150 Ω diff), shown before the calculation runs.
6. **Explicit published modelling parameters** (copper as modelled, soldermask C1/C2/C3/CEr, etch delta). Showing these openly is good; we should show them **in the result**, not only in a help article.
7. **Ranking presets by cost/lead time** is a useful extra column. We would need a fab profile field for it and must not hard-code it.

## 7) Weaknesses / what a more rigorous tool should do better

1. **Model not named, accuracy not stated.** No formula, solver, reference or accuracy class is given. Our `CalcResult` must give method, reference and confidence.
2. **Hidden assumptions.** Solder mask, trapezoid etch, and the finished-copper thicknesses are applied silently and are documented only in a separate article. In the UI they cannot be seen or changed.
3. **Precision that is not justified.** A width printed to 0.01 mil sits alongside ±20% track tolerance and ±10% impedance tolerance. We should round to a sensible number of figures and show the Z0 band when width varies ±20%.
4. **No analysis direction.** You cannot enter a width and get Z0, Er_eff, delay or loss, and there is no sensitivity view.
5. **No frequency, loss or roughness.** Er is given without a test frequency, and there is no Df or roughness input.
6. **Internal inconsistencies to flag (not to resolve silently):**
   - External 1 oz is modelled as 1.6 mil (≈ 0.0406 mm) in [GUIDE], but templates in [IMP] list outer copper as 0.035 mm. This may be plated versus base foil; neither page explains it.
   - Internal copper choices: [GUIDE] says 0.5/1 oz only, but the [CALC] dropdown showed 2 oz. External: [GUIDE] says 1 oz only, but the dropdown showed 2 oz.
   - 7628 thickness: 0.2104 mm in [IMP] versus "8.6 mil" (0.218 mm) in an unconfirmed snippet attributed to [GUIDE].
   - The Tg label conflict reported in [GS].
7. **Data errors in templates** ([Q590]). A rigorous tool should validate preset files (no missing fields, thicknesses that sum to the board thickness) when loading them.
8. **Disagreement with KiCad.** [KF] reports JLC width 0.1425 mm versus KiCad 0.16943 mm (F.Cu) and 0.1379 versus 0.14640 mm (In2.Cu) on JLC06161-3313B. That is about 19% and 6%, with no explanation available because JLC's method is not public. This supports showing the method and assumptions so users can work out such gaps.
9. **The JLCPCB trace-width blog [BLOG-TW] contains a substantive error, and it mislabels its standard.**
   - It says it is "based on IPC-2152", but the constants it uses (k = 0.048 external / 0.024 internal, b = 0.44, c = 0.725) are the IPC-2221 legacy chart-fit form. This is my identification and should be checked against ledger rows S-001/S-002.
   - Per the fetched description, the result of (I/(k·ΔT^b))^(1/c) is assigned to `width_mils` and used **directly as width**. In the IPC-2221 form that quantity is a **cross-sectional area in mil²**, and copper thickness is not used in that mode.
   - Example by hand, not ledger-verified: for 1 A, ΔT 10 °C external, the expression gives ≈ 16.3 mil². The blog would show 16.3 mil width. Dividing by 1 oz ≈ 1.378 mil gives ≈ 11.8 mil.
   - A human should re-read the article in a browser to confirm, because this came through a summarising fetcher.
   - Lesson for us: show dimensions next to every intermediate result (rule 6), and never let a fab blog be a source for formulas or labels.

### 9b. Proposed field list for the restructured profile

Principle: one entry per published limit, each carrying its own scope, so a check can pick the entry matching the board and never fall back to a less strict one silently. Proposed entry shape (names are a proposal for calc-implementer; the schema is theirs):

```
{ key, kind: 'min' | 'recommended-min' | 'max' | 'tol-plus' | 'tol-minus' | 'tol-sym' | 'average',
  value, unit, published: true | false,            // false = "not published", value null
  holeType?: 'via' | 'pth' | 'npth' | 'pressfit' | 'slot-plated' | 'slot-npth',
  sizeBasis?: 'finished' | 'drill' | 'designed-unstated',
  layerCount: '1' | '2' | '1-2' | 'multilayer' | 'any',
  copperOzFt2: number | 'any',
  layerSide: 'inner' | 'outer' | 'unstated',
  ledgerId, quote }
```
